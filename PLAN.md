## 2. Ідея проєкту

Мобільний застосунок: користувач фотографує хворе листя рослини, застосунок надсилає фото на Python API, бекенд повертає діагноз і поради з догляду.

## 4. Дані та навчання моделі

- Є мала кількість розмічених зображень хворих рослин і велика кількість сирих нерозмічених.
- Підхід: semi-supervised learning через pseudo-labeling (схема teacher/student):
  1. Навчити ResNet на розмічених даних (teacher).
  2. Передбачити мітки для нерозмічених даних.
  3. Розширити датасет відфільтрованими псевдо-мітками.
  4. Навчити student на розширеному датасеті.
- Експерименти трекаються у W&B, дані версіонуються через DVC.

## 5. Функціональність

- Клієнт: зробити або вибрати фото, надіслати на API, показати діагноз і поради з догляду.
- API: прийняти зображення, прогнати через модель, повернути діагноз і поради.
- Фідбек-цикл: користувач може підтвердити або виправити діагноз, ці дані зберігаються для подальшого донавчання.
- Автентифікація і зберігання зображень через Firebase.
- Адмінка (SQLAdmin) для перегляду даних і фідбеку.

## 8. Відкриті питання та уточнення

- **Тип класифікації**: Бінарна (`healthy` проти `sick`). Поради замінено на Grad-CAM візуалізацію зони уваги нейромережі.
- **Метрики якості**: F1-score (macro), Recall для класу `sick`, PR-AUC / ROC-AUC.
- **Pseudo-labeling**: Початковий поріг впевненості 0.95 з моніторингом перекосу класів та балансуванням. Підбір порогу на `val`, фінальна оцінка на `test`.
- **Логування експериментів**: TensorBoard + локальні CSV логи (W&B як опція за наявності API ключа; DVC відкладено).
- **Зберігання даних і фідбек**: Локально на бекенді (PostgreSQL + локальна директорія для зображень); Firebase Auth/Storage відкладено в беклог.
- **Підключення мобільного клієнта**: Для Android (USB-дебаг) — `adb reverse tcp:8000 tcp:8000`; для віддаленого/iOS тестування — Cloudflare Tunnel / ngrok.
- **Вимоги кафедри до оформлення теоретичної частини**: Будуть надані після виконання практичної частини.
