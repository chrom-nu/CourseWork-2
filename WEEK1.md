# WEEK1.md — Тиждень 1: репозиторій, дані, baseline-модель

> Використовується разом із PLAN.md (стек, рішення, правила для виконавця). Якщо цей файл суперечить PLAN.md, діє PLAN.md.

## Мета тижня

Отримати відтворюваний baseline: ResNet34, навчена на розмічених даних, з метриками на `val`. Це teacher для pseudo-labeling у тижнях 3–4.

## Обсяг

Входить: структура репозиторію, перевірка датасету, DataLoader, скрипт навчання, оцінка, логування.
Не входить: pseudo-labeling, Grad-CAM, API, Flutter, Firebase, DVC.

## Завдання

### 1. Репозиторій і середовище

- Створити структуру `ml/`, `backend/`, `mobile/`, `PLAN.md`, `WEEK1.md`, `.gitignore` (датасет, чекпойнти, `.venv`, логи не комітити).
- У `ml/`: `requirements.txt` із зафіксованими версіями, `README.md` з командами запуску.
- Розпакувати `dataset-nix.zip` у `ml/data/` (папка в `.gitignore`).

**Готово, коли:** `pip install -r requirements.txt` на чистому venv проходить, `python -c "import torch; print(torch.cuda.is_available())"` виводить `True`.

### 2. Перевірка датасету

- Підрахунок зображень по кожній частині і класу; звірити з очікуваним: train 170/432, val 59/143, test 55/147, unlabeled 5001.
- Перевірка цілісності: кожен файл відкривається, без нуль-байтових і пошкоджених.
- Статистика розмірів і співвідношень сторін, перелік форматів і колірних режимів (RGB / grayscale / RGBA).
- Перевірка на дублікати і майже-дублікати (хеш файлу і перцептивний хеш) **між** train, val, test і unlabeled. Особливо: чи немає перетину unlabeled із val/test.
- Результат: `ml/reports/dataset_report.md` або `.json`.

**Готово, коли:** звіт містить таблицю лічильників, список проблемних файлів (або явне «не знайдено») і список знайдених дублікатів між частинами.

### 3. Dataset і DataLoader

- `ml/src/dataset.py`: клас датасету для розмічених даних (мітка за назвою папки: healthy=0, sick=1) і окремий для unlabeled (без міток, поверне шлях і зображення).
- Трансформації:
  - train: resize, випадкове обрізання, горизонтальне/вертикальне віддзеркалення, невелика зміна кольору/яскравості, нормалізація за ImageNet;
  - val/test/unlabeled: лише resize, центральне обрізання, нормалізація.
- Розмір входу зробити параметром (початково 224).
- Зберегти візуальну сітку з 16 прикладів після аугментацій у `ml/reports/` для перевірки на око.

**Готово, коли:** DataLoader віддає батчі правильної форми, сітка прикладів збережена, `num_workers` працює на Windows без помилок.

### 4. Скрипт навчання baseline

- `ml/src/train.py` з аргументами командного рядка: архітектура (`resnet34`/`resnet50`), epochs, lr, batch size, seed, розмір входу, використання ваг класів.
- Модель: ResNet з ImageNet-вагами, останній шар замінений на 2 виходи.
- Loss: `CrossEntropyLoss` з вагами класів, обчисленими з train (через дисбаланс 170/432).
- Фіксація seed для відтворюваності.
- Збереження найкращого чекпойнта за **macro F1 на `val`** і останнього чекпойнта.
- Логування метрик кожної епохи (train loss, val loss, macro F1, recall для `sick`) у CSV. Якщо рішення по W&B ухвалено, додатково в W&B.

**Готово, коли:** повний запуск на GPU завершується без помилок, у `ml/runs/<назва>/` лежать конфіг, лог метрик і чекпойнти.

### 5. Скрипт оцінки

- `ml/src/evaluate.py`: приймає чекпойнт і розбиття, виводить macro F1, recall/precision/F1 по кожному класу, confusion matrix (зображення і числа).
- Оцінку на `test` запускати **один раз**, для фінального baseline, після того як конфігурація зафіксована за `val`.

**Готово, коли:** скрипт відтворює метрики `val`, які записав train.py, з розбіжністю в межах похибки.

### 6. Підсумок тижня

- `ml/reports/week1_summary.md`: фінальна конфігурація, таблиця метрик `val` (і `test`, якщо запускали), порівняння ResNet34 із ваговими коефіцієнтами і без них (мінімум 2 запуски), знахідки зі звіту про датасет, відомі проблеми.
